# RevolveRelate agent notes

- Source of truth is `spec/`. Do not emit SQL from an SLM.
- `build()` writes `.revolverelate/build.json`. Live `promote` is illegal until `status=complete` and sandbox validation is saved.
- Dummy sandbox never copies live critical/pii values.
- Python and TypeScript compilers must match `spec/fixtures/*.json` byte-for-byte.
- Warehouse engines in the catalog compile always; live execute is tier A only.
- MCP: `rr_boot` any catalogued DSN (parse schema, dummy stage, auto-chunk non-PII text). Atoms bind from that schema — not Superstore-only. Chain RelOps; `rr_question` any business, retrieve, or causal question (including “what causes …”) — dummy ticket, then the same RelOp on live. Never emit SQL. OverlayChunk is virtual; live overlay is TEMP from live text only.
- Tutorial: `docs/tutorial.md` and `python -m revolverelate tutorial`. Superstore facts, overlay RAG/semantic/causal chunks, then gene automine + cited report.
- Gene / FASTA domain: `spec/domain-gene.json` + `python -m revolverelate gene`. Public NCBI protein FASTA (DICER1/RB1/DROSHA/DGCR8) plus abstracts. Bind KPIs (`cases_by_gene`, …) when those columns exist. Ask “what causes pinealblastoma” — RelOp + overlay cues, not a discovery claim.
- Automine: `spec/automine.json` + `python -m revolverelate automine`. Domain-neutral: `domain/registry.py` detects the domain from the booted schema via each `spec/domain-*.json` `automine.detect` columns (gene, finance ship). Each pass recalls remembered evidence, re-causes, **gates** the pass Kineteq-style (`supported` / `review_required` / `refused` / `failed` — refused means nothing to pair, so nothing is invented), collects **possible-cause evidence** (heuristic, identification none — not proof), remembers it in the vector overlay, splices cues/candidates, pivots, expands catalogued `followOn`. A finished run is reused by `reuseKey` (domain + question) unless `rerun`. MCP: `rr_automine`, `rr_recall`, `rr_kpi`, `rr_gene`, `rr_finance`.
- Finance domain: `spec/domain-finance.json` + `python -m revolverelate finance` (`pip install revolverelate[finance]` for yfinance; otherwise baked seeded bars, `Source=baked`). Tables Ticker / PriceBar / PriceMove / MarketEvent. Moves are flagged from the bars (return z-score, volume ratio, gap, regime) and described with **templated cue notes** — cues restate measured facts so `chunk_causal` can pair them; they are not causal claims. Ask “what causes AAPL price moves”: evidence rows are per ticker × driver (volume spike / opening gap / trend regime / earnings reaction). Follow-ons are catalogued sector peers named in live `Peers` text. Not a forecast, not investment advice. Do not copy Kineteq’s LLM-found news / Bayesian posteriors.
- Evidence memory (vector store): `domain/evidence_store.py`. Evidence rows become `OverlayChunk` rows under the virtual entity `AutomineEvidence` (semantic + causal chunks, same hash-16 embed). `rr.recall(question)` / `rr_recall` run the same RelOp `overlay → chunk_* → knn`. Chroma syncs from the same table when opted in. Memory is restored after the rebuild that follows expansion. Never a live table.
- Autonomy loop on atomic relations: `spec/autonomy.json` + `python -m revolverelate autonomy --objective "..."`. Goal binds (measure/dimension/slice) → seed atom chains → `check_chain` (illegal chains never reach the sandbox) → dummy rollout → goal score → mutate one atom (swap bind, add restrict/cut/compare, finish, drop, splice) → keep winners in `.revolverelate/autonomy.json` → replay the winner live. Any booted schema, not Superstore-only. Score is a search heuristic. MCP: `rr_autonomy`. API: `rr.autonomy(objective)`. Never SQL; an SLM may only propose bind names.
- Self-directed hypotheses: `spec/hypotheses.json` + `python -m revolverelate hypothesize` (or `autonomy` with no objective / `--self`). Survey the booted schema → form hypotheses from five kinds (concentration, contrast, association, correlation, trend; each a statement with a declared threshold) plus autominer candidates and optional SLM proposals bound to listed names → test each as a RelOp chain: grammar check, dummy ticket, **verdict from live rows** (`supported` / `refuted` / `inconclusive` / `illegal` / `failed`; `dummy_only` when live is off and never counts) → derive follow-ups from supported results (drill into the winning slice, `refute_peers` records when a peer also passes) → remember every test in `.revolverelate/hypotheses.json` (never re-tested unless `retest`) and supported ones in the evidence overlay → run the atom search from the strongest supported hypothesis. Verdicts are threshold comparisons, uncorrected; not causal claims. API `rr.hypothesize()`, MCP `rr_hypothesize`.
- Deep research report: `spec/deep-research.json` after automine. Planner → researcher → reporter → validator. Citations are RelOp pairs, catalog NCBI/UniProt accessions, and bound KPI rows only — never invented papers. Local SLM (Ollama / OpenAI-compatible) or cloud API if `REVOLVERELATE_API_KEY` is set; otherwise a deterministic draft. MCP: `rr_report`. CLI: `python -m revolverelate report`. Identification remains none.
